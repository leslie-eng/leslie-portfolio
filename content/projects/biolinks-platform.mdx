## Approach

A contract engagement, delivered end to end. Off-the-shelf storefronts couldn't model how the business actually sells, and a spreadsheet "system" was holding everything together.

- **Architecture that fits the budget.** A React + Vite SPA on Vercel, a FastAPI API on Render, and PostgreSQL 17 as the single source of truth. Boring, cheap, and fully owned by the client.
- **Public site.** Product catalogue, the Dhibiti model, an Akiba savings calculator, a facility assessment and a chatbot entry point — built to be credible to medical customers.
- **Staff back-office.** Products, point of sale, orders, clients, finances and reports — the screens staff use every day, behind JWT auth with roles and bcrypt-hashed credentials.
- **Production discipline.** Schema changes go through versioned Alembic migrations. The web app and API deploy separately, and product images live on a dedicated uploads disk.

## Data quality & testing

- **16 backend test modules (pytest)** covering access control, auth, password changes, POS sales, the storefront, rate limits, security headers, the error envelope and startup checks.
- **Migration tests.** A dedicated test applies the Alembic migrations, so a schema change that would break production fails locally first.
- **Frontend tests.** Vitest covers the HTTP service layer, with an end-to-end test setup alongside it.
- **Database-enforced integrity.** PostgreSQL constraints and SQLAlchemy 2 models keep the data consistent, not just the UI.
